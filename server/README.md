# Backend заявок и админка (версия на сайте-портфолио)

Версия сайта на https://kseniya-developer.ru/meet-at-the-library/ принимает заявки на бронирование. На GitHub Pages форма остаётся демонстрационной (без сервера).

- `app.py`: backend на Python (только стандартная библиотека) и SQLite. Принимает заявки, отдаёт статус по коду, защищённая админка.
- `admin/`: страница админки (`/meet-at-the-library/admin/`), закрыта паролем и от индексации.
- `set_password.py`: задаёт пароль администратора (вводится в терминале, хранится только хеш).
- `deploy/`: unit для systemd, фрагмент конфигурации nginx и скрипт выкладки `deploy.sh`.

Сборка для портфолио: `npm run build:portfolio` (режим `portfolio`, настройки в `.env.portfolio`: адрес API и ссылка «Вернуться на сайт портфолио»).

## Как это работает
1. Клиент отправляет форму, backend сохраняет заявку со статусом «новая» и возвращает код вида `A7K2PQ`.
2. Сайт запоминает код в браузере и каждые 15 секунд проверяет статус. Когда в админке нажимают «Принять», клиент видит уведомление на сайте: «Заявка принята».
3. Внешних рассылок нет: ни почты, ни SMS, ни мессенджеров. Клиент может проверить статус по коду в блоке «Уже оставляли заявку?».

## Защита
- Пароль хранится хешем (scrypt, либо PBKDF2, если в Python нет scrypt), вход ограничен 8 попытками за 10 минут с одного адреса.
- Сессия: подписанная cookie `HttpOnly`, `Secure`, `SameSite=Strict`, живёт 12 часов.
- Изменяющие запросы требуют заголовок `X-Requested-With` и совпадающий `Origin`.
- Заявки проверяются на сервере, есть ограничение частоты (5 заявок в час с адреса) и скрытое поле-ловушка для ботов.
- В журналах нет персональных данных. Заявки удаляются через 30 дней (`ARKA_KEEP_DAYS`).
- Публичный статус по коду не показывает имя и телефон.

## Первый запуск на сервере
```bash
bash server/deploy/deploy.sh host
ssh -t host 'runuser -u www-data -- env ARKA_DATA=/var/lib/arka-backend python3 /opt/arka-backend/set_password.py'
```
